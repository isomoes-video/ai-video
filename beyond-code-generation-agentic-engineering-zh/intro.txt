代码生成越来越快，为什么交付仍然缓慢？本视频根据 Nick Liffen 与 Philip Holleran 于 2026 年 11 月 6 日在 GitHub Blog 发布的文章，解读 Plan、Build、Verify、Observe 四阶段的智能体工程工作流。提交量增长并不自动等于生产力提升，评审与协作可能成为新的瓶颈。视频对原文引用的评审耗时研究作明确归因，不把研究观察当成所有团队的必然结果。

规划阶段，汇总分散上下文，将需求转化为带验收标准的 Issue；构建阶段，通过云端沙箱、隔离工作副本、会话连续性与共享项目知识推进独立任务；验证阶段，以聚焦的小型 PR、自动检查与修复支持人类评审；观察阶段，将日志、发布记录和客户反馈变成证据、回归测试与下一轮规划的输入。视频还提供一个明确标注的 API 变更教学示例，展示如何把模糊要求写成可验证计划。

核心结论：先从本周最痛的一个环节开始，让智能体帮助整理和执行，把开发者的注意力留给目标、取舍与结果判断。衡量价值时，不只看生成了多少代码，也看能否更可靠地交付。
