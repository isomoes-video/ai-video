PART 01

打好基础

版本控制、账号安全，与你每天都会用到的 Git 命令

版本控制

版本控制是什么？Git 又是什么？

版本控制会记录文件随时间的每一次改动，让你随时回溯——从此告别一堆 final_v2。

 Git

在本地运行的工具，世界上用得最广的版本控制系统。

 GitHub

托管 Git 仓库、支撑团队协作的云平台。

Git 的三个区域

 工作区 working

 git add

 暂存区 staging

 git commit

 本地仓库 local repo

随时用 git status 看自己在哪一步

账号与安全

注册账号，先把安全设置做对

开启两步验证（2FA）

  • 路径：Settings → Password and authentication
  • 把恢复码存进密码管理器，别只截图
  • 多一道验证，账号被盗风险大幅下降

打造个人资料 README

  • 新建一个与用户名同名的仓库
  • 其中的 README 会展示在你的主页顶部
  • 用它做自我介绍，是你的第一张名片
安全设置只需做一次，却能保护你在 GitHub 上的每一行代码。

必备命令

十个几乎天天都会用到的 Git 命令

命令作用
git config --global user.name设置提交身份
git init初始化一个新仓库
git clone <url>把远程仓库克隆到本地
git status查看改动与暂存状态
git add .暂存改动
git commit -m "message"保存一次快照
git switch -c <branch>新建并切换到分支
git push把提交上传到 GitHub
git pull拉取最新的改动
git merge <branch>把分支合并到一起

PART 02

建立你的第一个项目

创建仓库、用 Markdown 排版，走通 GitHub 工作流

仓库

创建你的第一个仓库

仓库（repo）是一个会追踪改动、保存历史、让多人无缝协作的项目文件夹。

四步建好

1从主页点击绿色的 New 按钮

2给仓库起个名字

3选择 public 或 private

4勾选添加 README

README

项目的门面，来访者第一眼看到的说明。

.gitignore

列出 Git 应忽略的文件：系统文件、依赖、临时构建产物。

license （可选）

声明别人能怎样使用你的代码。

Markdown

用 Markdown 轻松排版

Markdown 是一种轻量的纯文本格式化语言——几个符号，就能排出清爽的版式。

在 GitHub 上几乎无处不在，同一套写法通用：

README Issue Pull Request 评论
# 一级标题
**粗体**  *斜体*
- 无序列表项
1. 有序列表项
`行内代码`
[链接文字](https://github.com)

GitHub 工作流

GitHub 工作流：一套可反复使用的协作循环

日常协作几乎都在重复这六个步骤——熟练之后会变成肌肉记忆。

1. 克隆

把仓库复制到本地

2. 建分支

为改动开一个分支

3. 改动

编写你的代码

4. 提交

保存改动快照

5. 推送

上传到 GitHub

6. 开 PR

发起拉取请求

给分支起个能说明意图的名字，比如 fix-login-bug 或 add-dark-mode。

PART 03

与他人协作

拉取请求、合并与冲突，以及议题和项目板

拉取请求

Pull Request：把改动摆上台面讨论

拉取请求（PR）是把一个分支的改动合并进另一个分支的提案，并自带一块供队友评审、讨论的空间。

直观展示改动的 diff 对比 支持同行评审与逐行讨论 PR 越小，越好评审、越低风险

 add-dark-mode → main

  function toggleTheme() {
-  setTheme('light') +  setTheme(saved ?? 'dark')   }

合并与冲突

合并，以及如何化解冲突

多数合并，一键完成

PR 审查通过后，点一下 Merge pull request，改动就进了主分支。

当两个分支改了同一行

Git 无法替你决定，就会标出冲突：

<<<<<<< HEAD
setTheme('light')
=======
setTheme('dark')
>>>>>>> add-dark-mode

解决三步：在浏览器或 VS Code 里选定保留哪一版 → 标记 resolved → 合并。

议题与项目

用 Issues 和 Projects 管理工作

Issues 议题

  • 追踪任务、bug 与想法
  • 可指派给人、打标签分类
  • 每条讨论都留有记录

Projects 项目板

  • 把议题排到看板上
  • 待办 / 进行中 / 完成，状态一目了然
  • 团队进度尽在掌握

自动联动：在 PR 描述里写下关闭关键词 Closes #42、Fixes #42 或 Resolves #42，合并时会自动关联并关闭对应议题。

PART 04

让项目更上一层楼

自动化、免费托管、代码安全，与迈向开源

GitHub Actions

用 GitHub Actions 自动化重复工作

GitHub Actions 是内建于 GitHub 的 CI/CD 与自动化平台。

当仓库里发生事件时，自动帮你跑测试、部署、打标签等任务。

  • 工作流写成 YAML，放在 .github/workflows/
  • 指定触发事件与要执行的步骤
  • 把重复的活儿交给机器
name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm test

GitHub Pages

用 GitHub Pages 免费托管网站

  • 静态网站免费托管，无需服务器
  • 在 Settings → Pages 一键开启
  • 私有仓库也能用（输出站点是公开的）
  • 作品集、项目文档的理想之选
  your-name.github.io

你的作品集

上线即公开，人人可访问

username.github.io/repo-name

代码安全

内建的三道安全防线

GitHub Advanced Security 的这些能力对公共仓库免费，在仓库设置里即可开启。

Secret scanning

揪出误提交的 API 密钥与凭证，防止泄露。

Dependabot

监控依赖中的漏洞，自动开出升级 PR。

CodeQL

分析代码的数据流，发现潜在的危险模式。

安全不该是事后补救——让平台在每次提交时替你把关。

参与开源

迈出参与开源的第一步

开源软件的代码人人可读、可改进，而 GitHub 正是它的家。

 怎么找到合适的项目

  • 看是否有清晰的 README、CONTRIBUTING.md 和开源 license
  • 寻找标着 good first issue 的议题

Branch 与 Fork 有何不同

Branch 分支

同一个仓库内部的平行工作区，你有权直接编辑。

Fork 派生

别人仓库的个人副本——给开源项目贡献时用它。

典型流程  Fork 项目  在 fork 里建分支  向原仓库开 PR
