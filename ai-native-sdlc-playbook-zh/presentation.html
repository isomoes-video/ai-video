03 · 构建：默认从 Plan mode 开始

BEFORE CODE

先把风险暴露在文档里，改变方向只需改字，而不是返工代码。

1 · 输入

intent.md + spec.md

2 · 追问

会破坏什么？最危险哪一步？有哪些备选？

3 · 提交

plan.md 写明文件、顺序与验证。

4 · 执行

批准后一次实现；偏离计划时同步更新计划。

把知识与控制写进仓库

CONTEXT

CLAUDE.md

命令、约定、架构与常犯错误。

“同一个错误出现两次，就写进去。”

KNOWLEDGE

Skills

把安全标准、API 规范、品牌规则变成可触发的组织能力。

建议性控制

ENFORCEMENT

Hooks

保护路径、格式化、凭据扫描与审批门禁。

确定性控制

Skill 让违规变少；Hook 让关键违规几乎不可能发生。两者变更都像代码一样审查。

并行化之前，先让验证闭环

PARALLELISM

Worktrees + Subagents

  • 独立任务进入独立 worktree
  • 重复验证工作封装为 subagent
  • 从 2–3 个并行 session 起步

FEEDBACK

Agent 自己检查自己

  • 统一的 test / build / screenshot 命令
  • Bug 先写失败测试，再修复
  • UI 用截图反复比较

并行上限不是能启动多少 Agent，而是人还能认真审查多少条工作流。

04 · 测试：从阶段门变成持续 Evals

20–50

个真实任务起步

每个任务包含 prompt 与可接受结果的检查条件。

何时运行

模型、prompt、CLAUDE.md、Skills 或 Hooks 变化时。

检查什么

测试、Lint、行为、政策与回归基线。

如何门禁

Pass rate 降低就阻止配置变更合并。

如何学习

每次生产事故都新增一个 Eval。

QA 不再追赶 Agent 产量，而是维护一套能跟上速度的活测试系统。

05 · 部署：AI 审查，但人类批准

REVIEW

REVIEW.md

按 Bug、安全、合规、spec 与 plan 分轮审查；PR 保留完整记录。

GATE

Hooks

每次都执行 allow / ask / block；不可绕过的规则放入 managed settings。

DELIVERY

CI/CD + MCP

Agent 可准备发布、调用受限工具；生产权限止步于明确门禁。

Agent 可以走到生产门前，但不能自己跨过去。
