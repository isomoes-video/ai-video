定义

什么是「智能体框架」（agentic harness）

它是编排层——负责管理工具、上下文与工作流，独立于底层模型之外。

模型负责“思考”，框架负责把每一轮的工具调用、上下文与记忆、限额与失败恢复编排起来。换模型，框架不变。

同一套框架，驱动 Copilot CLI、App、code review，以及 GitHub 与 Microsoft 的多处体验。

设计目标

  • 快：更短的端到端时延
  • 省 token：同样结果，更少消耗
  • 可预测：稳定、可复现的表现

架构

一套框架，驱动所有 GitHub Copilot 体验

模型路由 工具路由 上下文与记忆 限额与恢复 遥测与评估

框架经由 Copilot SDK 对外，承担上述五件事；模型可换，上层 CLI / App / IDE 体验不变。

方法

我们如何用基准测试持续迭代

四类信号交叉验证

  • 公共基准：行业通用标准
  • 内部基准：取自 GitHub 与 Microsoft 真实代码库
  • 真实使用指标：来自线上日常使用
  • 在线实验：A/B 验证每次改动

核心原则：控制变量

把 Copilot 框架与厂商自家框架放在同一条件下对比：

  • 相同模型、相同基准任务
  • 归一化上下文窗口与推理强度
  • 统一工具选择与 MCP 配置
尽可能控制每一个变量，让对比只反映框架本身的差异。

PART 02

评测结果

token 效率 · 任务完成率 · 成本与方差

token 效率

同样的任务，更少的 token

条形为同一任务、同一模型下 token 中位数（P50）的相对差异；负值＝Copilot 更省。

Claude 系列全面更省，最高 −65% GPT 系列多数更省（−5% ~ −39%） 唯一例外：SWE-bench Verified +7% / +4%

任务完成率

完成率与厂商框架基本持平

数值为完成率差异（百分点 pp）；正值＝Copilot 完成更多任务。

整体落在随机波动范围内 Win-Hill：各模型持平或更优 逐项有来有回，如 SkillsBench

完成率持平 ⟶ 底层模型的全部潜力得以释放。

TerminalBench 2

完成率 × 成本 × 方差：越靠左上越好

① 持平或更优

紫色 Copilot CLI 点完成率不落后、成本不更高。

② 波动可控

每个配置≥5 次运行，椭圆为 ±1σ；越小越可复现。

③ 模型权衡

GPT 成本最低、性价比高；Opus 完成率最高但更贵——都能选。

方法论

评测设置与重要说明

受控设置

  • 2 小时超时，非交互式单轮执行
  • 禁用 Web 工具，放开其余全部工具
  • 归一化上下文窗口与推理强度（中）
  • 指标统一为 pass@1；小型基准跑 5 次取最佳

读数前须知

  • 受控实验，不同于公开榜单成绩
  • 榜单常用更高推理强度与调优设置
  • 排除基础设施异常与网络影响以求公平
  • 基准只是众多信号之一
