中文标题：用 LLM 守护源代码安全
English Title: Using LLMs to Secure Source Code

Source: https://claude.com/blog/using-llms-to-secure-source-code

这期视频带你走完 Anthropic 工程博客最新提出的一套源代码安全工作流：怎么把 Claude 变成一支随时上岗的安全团队，用六步流程从威胁建模一路走到补丁验证。先抛一组关键数字——截至 2026 年 5 月 22 日，他们在开源世界共披露了 1596 个漏洞，但据他们了解只有 97 个被真正修上，而拥有完善威胁模型的团队，发现的漏洞约 90% 是真正可利用的。结论很直接：扫描已经可以轻松并行，瓶颈已经转移到验证、分诊和打补丁。

围绕这个论断，博客给出了一张"防守方的循环"图：左边两步是一次性投入——建立威胁模型、搭好沙箱；右边四步是反复跑的循环——发现、验证、分诊、修复。视频按这两段拆开讲。一次性投入部分强调，先用现有代码、CVE 历史和 Shostack 四问框架产出一份 THREAT_MODEL.md，把信任边界和关键资产写清楚；沙箱则同时承担安全护栏和"可利用性"实验台两个角色，容器跑静态分析，microVM 跑真正的 PoC，初始化后切断公网，并钉死依赖与 commit SHA 以保证结果可复现。

循环四步里，发现要给上下文而不是给 checklist，并行多个 agent 避免大家都收敛到浅层 bug；验证要专门起一个"全新环境"的 agent，核心思路是证伪而不是证实，靠对抗式验证团队把不可利用的误报降了大约一半；分诊要按根因去重，再从可达性、攻击者可控程度、前置条件、是否鉴权、影响范围五个维度打分；修复则要求先写一个会失败的测试再写补丁，过四关验收（构建成功、PoC 不再触发、回归通过、对抗复查），并顺手扫两层变种但不做无关重构。视频最后讨论了几个反直觉的经验——首次扫描数量最多、同代码也会出新结果、模型懂代码但不懂业务、人类还得在环里——并介绍了开箱即用的五个 skill：threat-model、vuln-scan、triage、patch、customize，以及 defending-code-reference-harness 参考实现和 Claude Security / GitHub Action 集成方式。
