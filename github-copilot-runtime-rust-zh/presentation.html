02 / 架构

同一引擎，两种承载方式

进程内

应用 → FFI → Rust

减少进程边界
与应用共享故障边界

进程外

应用 → 通信 → Rust 服务

保留独立进程
仍需通信与进程管理

Rust 重写完成 ≠ 所有客户端默认进程内运行

原文说明：进程内模式仍为主动选择；终端 UI 的分层工作仍在继续。

案例事实：原地逐组件替换；小步迁移期间保持主分支可发布。

08 / 工程解读

第一次试点，可以这样设计

选小组件　边界清晰，外部依赖少

冻结参照　先记录接口、样例与失败行为

跑完整链路　构建 → 接入 → 测试 → 发布

再做决定　按缺陷与资源收益决定是否扩大

用试点发现真实成本，也检验团队是否能接手维护。

本片提出的试点方法；不是对所有项目的语言迁移建议。
